# Atomic dependency-closure provenance gate
Implement release_gate.py to stage a requested application together with its transitive pinned dependencies across independent signed repositories. A release is coherent only if every dependency path agrees on the same (repository,path) content, each repository's trust transition is valid, and all referenced bytes are verified. The actual request in data/input.json spans three repositories and a shared dependency, including expired-anchor recovery and delegated metadata. No online fetching is allowed; bundled metadata and bytes are the available evidence.

## API and atomicity
initialize(path,anchors), inspect(path), install(path,request). anchors maps repository name to a trusted root BODY (not envelope). initialize is idempotent for equal anchors and rejects different anchors. SQLite database mutations serialize across processes. inspect returns {version,at,repositories:{repo:{root_version,snapshot_version,roles:{role:version},installed:{path:{length,sha256}}}}}. Initially version 0, at=-1, root versions from anchors, snapshot_version 0, empty roles/installed. State and request responses survive restart.

request={id,expected_version,at,bundles:{repo:bundle},requested:[reference]}. reference={repo,path,sha256}. bundle={roots:[envelope],snapshot:envelope,metadata:{role:envelope},artifacts:{path:UTF8 string}}. An envelope={signed:body,signatures:[{keyid,sig}]}. Use supplied crypto.canonical and verify_signature; cryptography is not the repair. Exact structural request replay returns its original response BEFORE CAS, even after newer requests; changed payload/expected version for same ID fails. New requests require expected_version=current and at>=last successful at. Success increments version once and returns inspect summary plus installed:[{repo,path,length,sha256,role}] for this request's entire closure sorted by (repo,path), each identity once. Unrequested previously installed bytes remain. Failures raise ValueError with unconstrained message and must not persist ANY repository trust/cache/install/request changes. Inputs are not mutated.

## Per-repository trust (independent namespaces)
Only repositories reached from requested dependency closure are visited; unused bundles/roles may be invalid and must not poison the request. Unknown referenced repo or missing required material fails. All visited metadata uses request.at.

root={type:'root',version,not_before,expires,keys:{keyid:{n:hex,e:int}},roles:{root|snapshot|targets:{keyids,threshold}}}. Starting from saved root, each supplied successor must have version exactly previous+1 and not_before<=at<expires, be authorized by BOTH previous-root root role and successor root role over the SAME body. Distinct valid key IDs count; duplicated signatures do not. An expired previous root can authorize a valid successor; the final root must be unexpired. Never self-authorize an untrusted replacement.

snapshot body={type:'snapshot',version,expires,meta:{role:{version,length,sha256}}}. Verify final-root snapshot threshold and at<expires. Its version may not decrease; same version requires same BODY canonical digest. Every visited targets envelope must match its snapshot pin's version and ENTIRE canonical envelope length/hash, including signatures.

targets body={type:'targets',role,version,expires,targets:{path:{length,sha256,dependencies:[reference]}},delegations:[{name,paths:[glob],keyids,threshold,terminating:boolean}]}. Visit top 'targets' under final-root targets role; require matching role/type/version, unexpired metadata and authorized signatures. Every visited role version cannot decrease, and equal version cannot change body digest. A path directly present wins. Otherwise visit matching delegates in listed order using Python fnmatchcase; a found target wins. A terminating matching delegate miss terminates the ENTIRE lookup, propagating through ancestors (no sibling fallthrough), as does a descendant's terminating miss. Detect role cycles on the current recursion stack; DAG reuse across requests/paths is allowed. Metadata rollback state is updated for every visited role, but only on whole-install success.

## Dependency closure
Every reached descriptor's sha256 must equal the incoming reference pin. References with the same (repo,path) must all carry the same pin, including a shared diamond. Recurse through dependencies in declared order. A cycle in the current artifact recursion stack fails; repeated non-cyclic shared dependencies are verified once. Byte payload must be present, UTF8 length and SHA256 must match the signed descriptor. Dependency validation is as strict as the top request. Do not commit a trust update early simply because an earlier repository/branch was valid. Request success means the entire closure was staged atomically; it does not deploy to production.

Bounds: <=4 repositories,4 root successors/repo,12 roles/repo,12 artifact identities total,8 direct requests,20 install calls. Inputs well-shaped; authenticity, lookup/closure conflicts, rollback, expiry, missing objects, cycles and CAS are semantic failures. Canonical JSON is UTF8 sort_keys=True,separators=(',',':'), ensure_ascii=True. Protected: SPEC.md,data/,production/,pytest.ini,crypto.py. Edit release_gate.py/optional helpers and add tests; trusted baseline reruns independently and test additions/restructuring are allowed. Do not alter production/state.json.
