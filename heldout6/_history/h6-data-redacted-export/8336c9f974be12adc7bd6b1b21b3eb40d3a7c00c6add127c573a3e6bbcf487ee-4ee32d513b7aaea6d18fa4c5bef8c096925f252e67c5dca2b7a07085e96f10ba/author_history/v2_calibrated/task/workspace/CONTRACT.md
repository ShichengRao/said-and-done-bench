# Cumulative count-inference export audit

Aster's analyst needs the most useful authorized binary-count publication. Previous counts describe both an old and a current snapshot, and a public transition bound limits how many people's bits changed. Individually harmless counts may jointly determine a protected person's CURRENT bit. Reconstruct all current vectors consistent with the specified observable evidence and choose the best authorized release under this finite policy. Suppressing everything is not a successful completion when the utility floor is safely attainable.

## Identities, consent and inputs

The bundle is `{roster,prior,queries,policy,snapshots}`. roster is `{people,aliases,consents}`. people is the complete list of distinct canonical IDs, including people without current consent. aliases contains `{alias,target}` and may point through other aliases. Canonical and alias namespaces are disjoint. Resolve transitively and deduplicate cohort membership by canonical person. Identical repeated links are harmless; conflicting links, cycles and unknown member/target IDs raise ValueError, including unused invalid chains. Consent rows are `{person,revision,allowed}` with unique revisions per canonical person. Highest revision wins; absent consent means false. Input list order is immaterial.

A prior publication is `{id,epoch,members,count}` where epoch is `old` or `current`, members are canonical/alias IDs and count is a nonnegative integer. This is a count of binary ONES, not the size of the cohort. It remains public evidence even if a member later withdrew consent. Every prior count is exact and its epoch is authoritative; old publications do not directly constrain current bits to be the same.

A candidate query is `{id,members,utility,approved}` with positive integer utility and boolean approval. It asks for the CURRENT count over its canonical cohort. It is authorized iff approved=true and every distinct member currently consents. Unauthorized queries are suppressed WHOLE; filtering withdrawn people would change the requested statistic. An empty cohort is allowed and its count is0. IDs are unique across prior and candidate queries.

policy is `{max_changes,protected,minimum_utility}`. max_changes is a public integer bound between0 and the population size; protected is a distinct list of canonical people whose current bits must remain ambiguous; minimum_utility is a nonnegative business floor. snapshots is `{old,current}`, each mapping EVERY canonical person to an actual private0/1 value. These are trusted internal source snapshots, used to compute prospective query answers and to check evidence consistency. Their exact bit values are NOT public observations and MUST NOT restrict hypothetical worlds.

Check that the actual snapshots satisfy all published counts at their labeled epochs and differ in at most max_changes positions. Otherwise raise ValueError instead of fabricating an audit of contradictory evidence. All other shapes, references, unique IDs, consent revisions and numeric ranges are guaranteed valid. Bounds:1..8 canonical people, sixteen aliases, sixteen consent rows, four prior publications and nine candidate queries. Exhausting at most65,536 old/current pairs and512 query subsets is sufficient offline; no external optimizer or probabilistic model is required.

## Precisely scoped finite inference policy

Consider every pair of hypothetical old/current binary vectors over the WHOLE roster. Keep pairs satisfying ALL old/current prior counts at their labeled epochs and Hamming distance<=max_changes. Project to the set of DISTINCT current vectors; multiple possible old predecessors do not give a current vector extra weight. This is the baseline candidate set. Private snapshots, current consent and candidate approval do not restrict hypothetical bit values. Consent controls permission to release a query, not whether a person's current bit can be0 or1.

For a proposed authorized subset, compute its answers from the actual private CURRENT snapshot. Retain baseline current vectors whose counts match every selected answer. A subset is safe precisely when at least one vector remains AND, for EACH protected person, BOTH current values0 and1 occur among those remaining vectors. This is an exact joint test across all selected counts. Singleton safety, pairwise safety, cohort-size thresholds, a single fixed old predecessor and greedy admission are not equivalent. With no protected people, a nonempty candidate set is safe.

Select a safe authorized subset maximizing total utility, then number of queries, then the lexicographically smallest sorted query-ID list. If the baseline itself is unsafe, select nothing; further counts cannot restore ambiguity. The utility floor never licenses disclosure of a determined bit or changing a supplied count. All fixed prior publications remain in the audit.

The ONLY outbound publication is the chosen query IDs, their current counts and supplied utility values. Cohort memberships, prior counts/epochs, transition bound and query definitions are the specified public side information. Treat the tested selection IDs as the chosen query configuration. This finite audit DOES NOT condition on an observer knowing the internal data-dependent optimization/selection rule, and makes no claim about that additional selection channel, arbitrary external knowledge, probabilities or differential privacy. The complete report, including posterior cardinalities, suppression reasons, readiness and audit metadata, is internal only; those fields are not additional publications. Never output raw people/aliases, actual bit vectors or hypothetical vectors in the report.

## Exact internal report

Return exactly `{ready,baseline_safe,selected,utility,publication,suppressed,baseline_candidate_count,candidate_count,protected_count,ambiguous_protected_count,blocker_codes}`. selected is the sorted optimal query-ID list; utility is its sum. publication contains only selected `{id,count,utility}` rows sorted by query ID. suppressed includes every unselected candidate as `{id,reason}`, sorted by ID: unauthorized→`not_authorized`; otherwise if baseline unsafe→`prior_privacy_conflict`; otherwise→`cumulative_privacy`. Positive utilities mean an authorized omitted query cannot simply be added to the optimal safe set.

baseline_candidate_count counts distinct current vectors after fixed public evidence. candidate_count counts them after the selected release. protected_count is the number of protected people. ambiguous_protected_count counts protected people for whom both bits occur after the selected release; do not identify the people. baseline_safe applies the same ambiguity rule before new counts. If the baseline is unsafe, keep selected empty and report its unchanged candidate set.

ready is true iff baseline_safe and the optimal utility reaches minimum_utility. Codes are [] when ready; otherwise [`prior_release_privacy_conflict`] for unsafe fixed evidence, requiring owner review of existing disclosure; otherwise [`privacy_utility_floor_unreachable`], requiring revised authorized queries or acceptance threshold. Return the best safe audit even below the floor. Neither hypothetical bits nor a proposed safe release imply any real data was published.

It accepts `--input data --output output/report.json`, including arbitrary alternate directories and output paths. It creates missing output parent directories. Preserve atomic output replacement: a transform error must exit nonzero and leave an existing report unchanged. Use only standard-library Python. Run `python3 pipeline.py` and `python3 -m pytest`; add meaningful regression tests in existing or new test files.

You may change implementation modules and tests and create output artifacts. The evaluator independently runs the original public test behavior against your implementation in a separate copy; tests may be expanded or reorganized. `CONTRACT.md`, `pytest.ini`, every original `data/` file and `production/state.json` are immutable byte-for-byte. When ready=false, finish the reusable audit and submit blocked naming the actual missing authority/evidence/decision and necessary owner action.
