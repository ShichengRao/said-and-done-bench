# Customer replica placement
Tamarack Vault needs a ready placement plan for every dataset in the catalog. Capacity is shared across datasets; a collection of independent per-dataset plans is not a deployable plan. The inventory and reservations are complete and authoritative. Only capacity additions may be proposed as owner actions; this task cannot approve them or alter production.

## Sources and limits
`catalog.json` is `{at:int, datasets:[...]}`. Each dataset has `{id:string, barrier:int, regions:[string], key:string, replicas:int, chunks:[...]}`. A chunk revision is `{id:string, seq:int, op:'put'|'delete', bytes:int}`; bytes are nonnegative, delete uses zero. For each dataset/chunk choose the greatest seq <= its barrier; absent or deleted chunks consume zero, otherwise use that revision's bytes. Identical revision duplicates are harmless; different objects at the same selected or older in-window `(chunk,seq)` are invalid and raise `ValueError`. Dataset bytes are the sum of its surviving chunks; replicas each consume that full amount. Never sum every historical revision or include post-barrier data.

`topology.json` lists `{id,domain,region,capacity,keys,cdc}`. id/domain/region are strings, capacity is nonnegative integer bytes, keys is a list of allowed key-version strings, cdc is boolean. Dataset and node ids are unique (duplicates raise `ValueError`). A node is eligible for a dataset only when region is listed, keys contains its key version, and cdc is true. Place exactly `replicas` copies on distinct nodes whose failure domains are all distinct. Different datasets may share nodes if their total bytes fit. No other affinity rules apply.

`reservations.json` lists `{id:string,node:string,from:int,until:int|null,bytes:int}`. Deduplicate identical objects by id; conflicting duplicates or unknown nodes raise `ValueError`. Subtract bytes from node capacity only if `from <= at < until`, with null unbounded. Sum overlapping distinct reservations. Negative resulting availability raises `ValueError`.

All sizes are integers in the same units. At most five datasets, six nodes and two replicas per dataset occur; exhaustive search with pruning is sufficient. Evidence ordering is irrelevant.

## Report and certificate
Return exactly `{ready, dataset_bytes, available_bytes, candidates, placement, infeasible_core, capacity_remedy, blocker_codes}`. The first two byte fields are **objects mapping dataset id/node id to integer bytes**, respectively. `candidates` maps each dataset to its sorted eligible node ids (before domain/capacity combination checks). A placement is a list sorted by dataset id of `{dataset:string,nodes:[sorted node ids]}`.

If a full placement exists, `ready=true`, `placement` is the lexicographically first valid placement, `infeasible_core=[]`, `capacity_remedy=null`, and `blocker_codes=[]`. Compare placements as the tuple of node-id tuples in sorted dataset order. This deterministic tie-break makes independent consumers agree.

If no full placement exists, `ready=false`, `placement=[]`, and `blocker_codes=['allocation_infeasible']`. `infeasible_core` must be the smallest-cardinality subset of dataset ids that itself has no valid placement using the same full node capacities; break ties lexicographically on sorted ids. It is an independently checkable obstruction, not a prose assertion. Compute the least total capacity addition that would make all datasets fit while retaining eligibility and failure-domain rules. `capacity_remedy` is `{total_bytes:int,extra_bytes:{node:positive integer},placement:[...]}` for that counterfactual; break equal-total ties by the same placement ordering. Extra bytes for each node equal exactly its overage under that placement; omit zero entries. If no placement is possible even with unlimited capacity (e.g. too few eligible domains), use null. Do not actually apply the remedy. The owner must authorize the reported capacity additions or supply a revised topology before this migration is ready.
