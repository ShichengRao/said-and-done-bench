# Procurement baskets across warehouse transfer events

Implement `procurement.initialize(path,stock,transfers)`, `procurement.apply(path,command)`, and `procurement.snapshot(path)` using standard-library SQLite. Procurement baskets reserve several SKUs atomically; workers may amend their warehouse routes while transfer webhooks arrive out of order. Incoming stock must never be counted twice or spent before its source debit. A single transactional JSON state row is acceptable. Records are fictional. SPEC.md and data/ are immutable. Code and tests can be edited/added, with original examples rerun independently.

## Seed and identity
stock is a list of unique `{warehouse,sku,quantity}` pairs with nonnegative integer quantity. transfers is a list of unique `{id,source,destination,lines}`; lines maps SKUs to positive quantities, source != destination, and all source/destination stock pairs exist. IDs contain ASCII letters/digits/hyphens. initialize returns None and creates clock 0, those physical stock balances, no baskets/history, and each manifest's transfer state `{id,observed:[],status:'waiting'}`. Reinitializing with semantically identical seed lists in any order is a no-op; changed seed raises ValueError without alteration. Parent directories exist.

Commands have operation_id, at, kind and the fields below. All input shapes/types are valid; quantities are positive, at >=0, requests have 1–4 needs, request routes have exactly matching keys and nonempty duplicate-free warehouse lists. Inputs must not be mutated. Accepted operation IDs permanently identify the entire JSON command, dictionary order irrelevant, list order meaningful. Identical retries return the original response BEFORE time/expiry/version checks; altered reuse raises ValueError. Rejected operation IDs remain reusable. All checks, stock mutations, identity and history writes belong to one transaction and survive restart.

A new operation requires at >= clock. Tentatively expire EVERY held basket with expires <= at: status expired and version increment once, releasing its holds while retaining its plan. Any rejected operation raises ValueError and rolls back everything, INCLUDING these expirations. Accepted unavailable results commit clock/expiry. No wall clock is used.

## Basket lifecycle
reserve has `{basket,until,request}`; request is `{needs,routes}`, needs maps SKU to quantity, routes maps each SKU to an ordered warehouse list. Basket ID must not exist and until > at. For SKUs sorted lexicographically, take requested quantity greedily from available physical stock along its route. Available is on_hand minus ALL currently held basket allocations. Validate every supplied warehouse/SKU pair even after enough stock was found; an unknown pair raises ValueError. If any SKU cannot be fully supplied, return unavailable with basket null: create no partial reservation and the ID remains reusable. Otherwise create version 1, status held, expires until, the request and allocations sorted by SKU then route order (omit zero allocations). Each allocation is `{sku,warehouse,quantity}`.

amend has `{basket,expected_version,until,request}`. Requires an existing held basket after tentative expiry, exact version, and until > at. Replan the whole replacement basket, making its OWN old hold available while keeping every other basket's hold. If feasible, replace request/plan/expiry together and increment version once, result amended. If infeasible, result unavailable with the unchanged old basket object; retain its old plan, expiry and version. Other due expirations and clock still commit. Never drop the old hold to make a failed amendment partially succeed. Unknown routes and stale/terminal versions raise ValueError and roll back the whole operation.

commit and release each have `{basket,expected_version}` and require a held basket with exact version. Commit subtracts each reserved allocation from physical stock and sets status committed. Release only sets status released. Both increment version once and retain request/plan/expiry for audit; terminal plans no longer hold stock. Basket object is exactly `{id,version,status,expires,request,allocations}`. Terminal basket IDs are not reusable.

## Transfer webhook processing
receive has `{transfer,event}`; transfer must be a seeded manifest ID and event is depart or arrive. Record the event as observed (sorted unique strings). A duplicate physical event with a NEW operation ID is an accepted no-op for stock, although it has its own response/history entry. If depart is observed and status waiting, check ALL source lines against available stock AFTER tentative expiry; insufficient source stock raises ValueError and rolls back the whole call, including the newly observed event. Otherwise debit all source lines atomically and set in_transit. If arrive is observed and status in_transit, credit destination lines once and set arrived. Process these transitions in that order inside the SAME transaction. Thus an early arrival is buffered in waiting state with no stock credit; when departure later succeeds, both transitions occur. A prior buffered arrival survives a later failed departure because it was committed earlier. Manifests are immutable, and a receive event cannot change their quantities or route.

## Response and snapshot
Each accepted call returns exactly `{operation_id,result,basket,transfer}`. Result is reserved, amended, unavailable, committed, released or received. Basket is the post-operation object (or null for receive/failed reserve); transfer is the post-receive state (or null for basket operations). Historical responses are immutable: later amendments, expirations and receipts cannot alter earlier returned or stored objects.

snapshot returns exactly `{clock,stock,baskets,transfers,history}`. Stock rows sort by (warehouse,sku) and are `{warehouse,sku,on_hand,held,available}`. Baskets/transfers sort by ID. History is accepted responses in commit order, exactly once per operation ID. Read one coherent durable state without advancing time. Any serial result from concurrent callers is valid; no particular worker must win. Never return objects sharing mutable identity with caller inputs or future durable state.
