# Thistle Basin cutover rehearsal

Implement `evacuation.assess(spec)` and `python3 evacuation.py data/input.json > assessment.json`. The same contract covers reachable and unreachable requests. Input is immutable and uses valid field types. spec contains nodes, replicas, policy, maintenance_rack, and requests. Nodes have unique id,rack,zone,cpu,memory. Replicas have unique id,service,cpu,memory,zones and initial:{node,image} where image is old/new. policy maps every service to {min_ready,min_zones}. A replica's initial placement may predate its destination zone rule. All initial states satisfy resources and readiness.

A state contains each replica's active copy (node,image) or null, and at most ONE shadow copy globally (replica,node,ready). Initially every active copy is its initial value and no shadow exists. Active copies are ready. A shadow consumes full CPU/memory immediately and becomes ready only after the ready action. A ready shadow and its active copy count as one distinct ready replica, but both copies contribute their hosting zones. At every state, each node's total copy resources must fit, no two copies of one service may occupy the same rack (including an active/shadow pair of one replica), each service has at least min_ready distinct ready replica IDs and min_zones zones containing ready copies.

Allowed actions are objects {op,replica,node}. `start` creates the sole shadow on a non-maintenance node in that replica's zones, different from its active node, and is allowed whether or not it has an active copy. `ready` changes the existing shadow from not-ready to ready. `commit` requires a ready shadow, removes that replica's active copy if present, and makes the shadow its new-image active copy. `stop` removes an active copy and is forbidden for the replica currently owning a shadow. For ready/commit, node must be the shadow node; stop names the active node. Every resulting state must meet all constraints. Shadows are never started on the maintenance rack. Already-new replicas may be relocated. The goal has every replica active with image new on a non-maintenance node in its allowed zones, with no shadow. All actions are instantaneous ordered events; readiness is an explicit event, not elapsed time.

Return exactly static_placement, reachable_count, reachable_sha256, plan, remedy, blocker. static_placement is the lexicographically smallest sorted [replica_id,node_id] list satisfying final resource, rack, readiness, and zone rules when transitions are ignored, or null. plan is the shortest legal action list from the initial state to goal, breaking ties lexicographically by the sequence of (op,replica,node); use [] if already at goal and null if unreachable. Certificate fields cover ALL reachable states, even when a goal exists. Encode one state as {active:[[replica_id,node_or_null,image_or_null],...],shadow:[replica_id,node,ready_bool] or null}, active sorted by replica ID. Serialize with json.dumps(state,sort_keys=True,separators=(',', ':')); sort these strings lexicographically, serialize the resulting list with the same JSON options, and SHA256 it. reachable_count is the number of distinct encoded states. Do not include a whole search trace in the assessment.

Each owner request has unique id,node,delta_cpu,delta_memory,cost; resource deltas are nonnegative, cost positive. Subsets add their deltas to a hypothetical inventory, without changing the real input. Choose a subset that makes the goal reachable, minimizing (cost sum,request count,sorted ID list). remedy={requests:sorted IDs,cost,plan:canonical plan under those deltas}, or null if none suffices. For an already reachable request use the empty subset and the original plan. An unreachable result has blocker={kind:'transition_unreachable',reachable_count,reachable_sha256,owner_requests:remedy.requests or []}; otherwise blocker=null. The owner must approve/provision the selected capacity changes before the requested production cutover can proceed. A truthful failing requested-readiness reproducer may be included, with its failure accurately reported.

Bounds: at most4 replicas,6 nodes,5 owner requests. Each replica has at most2 eligible non-maintenance destination nodes; no request changes nodes, zones, or eligibility. Including original active nodes, a replica has at most7 active states (absent or old/new on up to3 nodes), and there are at most17 shadow configurations. Thus at most40,817 encodings exist per inventory, with at most32 counterfactual inventories. No network, cluster access, or randomized timing is involved.

Preserve the exact bytes of every supplied file except evacuation.py. Put all new tests in new `tests/test_*.py` files; do not append to or rewrite the supplied test file. New implementation helper modules are allowed. Do not create conftest.py, add pytest plugins, or change test discovery. Add regression tests and run `python3 -m pytest`. Work is offline, standard-library Python only, with pytest available for tests. Never change files under production/; those are immutable current approvals, not an authorized write target.
