# Authorized connector transaction route
Juniper Link needs to execute the entire ordered migration transaction using approved service credentials. Each stage may have authorized credentials while no valid end-to-end transaction route exists. The engineer may plan and demonstrate proposed owner changes, but cannot mint credentials, increase quotas, or approve handoffs.

## Sources
`request.json`: `{tenant:string,binding:string,entry:[credential_id],steps:[{resource:string,operation:string,at:int}]}`. Steps are in required execution order; their times are nondecreasing. Entry lists allowed credentials for the first step only. At most six steps, seven credentials, eight proposals.

`credentials.json`: unique objects `{id,parent,selectable,tenant,binding,from,until,revoked_at,capabilities,uses}`. Parent is a credential id or null; broken/cyclic chains raise `ValueError` even for an unused credential. Selectable is boolean: root delegators can be nonselectable. From is integer, until/revoked_at integer or null; uses is a nonnegative integer per-transaction operation quota. Capabilities are exact `[resource,operation]` pairs; do not independently union resources and operations. For a credential to perform a stage, it must be selectable and **every** credential on its parent chain must match the request tenant/binding, contain that exact pair, and be active at the stage's time (`from <= at < until` and `at < revoked_at`, with null unbounded). Delegated authority is the intersection, not the union. Quotas are charged only to the selected credential, not its parent.

`handoffs.json`: `{source:credential_id,target:credential_id,after:int,from:int,until:int|null}` entries. A handoff is allowed only immediately after that 1-based stage index and active at the next step's time. Staying on the same credential requires no handoff. Switching requires a matching active handoff. Quotas accumulate across the entire transaction; leaving and returning does not reset them. A step consumes exactly one use. Handoffs do not themselves consume uses. Identical handoffs are harmless.

`proposals.json`: unique `{id,cost,kind,...}` entries with positive integer cost. A `quota` proposal additionally has `{credential,extra:positive int}` and adds uses. A `handoff` proposal has `{link:<handoff object>}` and adds that link. Proposals are future owner actions, not current authority. They do not alter scopes, entry, identity binding or time validity. Evaluate subsets additively; all references exist. All evidence lists except request.steps are unordered.

## Output and reachability certificate
Return exactly `{ready,candidates,path,frontiers,owner_remedy,blocker_codes}`. `candidates` lists `{step:1-based int,credentials:[sorted ids]}` for every step using only chain authorization (before entry/handoff/quota constraints). A `path` is the selected credential id per step; use the lexicographically first valid full path.

`frontiers` contains one `{step,states}` per step. A state is `{credential,uses:{credential:positive count},path:[ids]}` representing a reachable endpoint and cumulative use vector. Include **all distinct** reachable `(credential,use vector)` states; when several paths reach one state retain its lexicographically first path. Sort states by credential then the tuple of counts in sorted all-credential-id order (including implicit zeros). Omit zero use-map entries. Empty frontiers remain present after reachability is lost. This finite certificate must be computed, not guessed from individual candidate availability.

If a full path exists, ready is true, owner_remedy null and blocker_codes empty. Otherwise ready is false, path empty and blocker_codes `['authorized_route_unreachable']`. Find the proposal subset with minimum total cost that creates a valid full route; tie-break by its sorted proposal-id tuple. Return `owner_remedy={proposals:[sorted ids],cost:int,path:[ids]}` with its lexicographically first route, or null if none works. Recommendations are counterfactual; only owner-approved current authority permits completion of the requested transaction.
