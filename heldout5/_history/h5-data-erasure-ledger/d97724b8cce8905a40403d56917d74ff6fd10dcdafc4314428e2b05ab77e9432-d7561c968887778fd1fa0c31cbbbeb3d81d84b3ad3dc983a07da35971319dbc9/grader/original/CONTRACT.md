# Erasure across derived customer records
Kestrel Desk needs a complete logical suppression and physical erasure plan through the CDC cutover, while honoring active evidence holds. A held copy can remain physically retained but must never remain in the customer-facing current set if it is subject to erasure. Rebuilt clean materializations must remain usable.

## Sources
`catalog.json`: `{watermark:int,cutover:int,at:int,versions:[version],heads:{object_id:version_id}}`. A version object has string `version` and `object`, `parents:[version_id]`, `identities:[{tenant:string,alias:string,at:int}]`, and arbitrary other JSON fields. Each parent is the exact source version used to derive the child, not the parent's current head. All ancestors must be present; cycles or missing parents raise `ValueError`. Identical version duplicates are harmless; conflicting objects for one version id raise `ValueError`. All version objects, including payload/metadata, must be preserved exactly in survivors. Snapshot heads refer to an existing version with the same object id or are invalid.

`changes.json`: unordered list of `{seq:int,object:string,op:'put'|'delete',value?:version}`. Only `watermark < seq <= cutover` is replayed in sequence order. A put makes value the current version and adds it to the immutable version store; its object must equal the event object. A delete removes only the current head, retaining history for lineage/holds. Deduplicate identical in-cutover sequence entries; conflicting entries with the same seq <= cutover raise `ValueError`, including covered events. Future rows are ignored. Covered rows do not alter or validate their payloads. Existing version conflicts and object mismatch during replay raise `ValueError`.

`identity.json`: `{tenant,alias,subject,from,until}` rows, identifiers strings and times integers, until nullable. Resolve every direct identity in the resulting version store at its own identity.at using `[from,until)`, null unbounded. Exactly one distinct subject must match; otherwise raise `ValueError`. Duplicate equivalent mappings are harmless. Identity keys are tenant-scoped and aliases can be recycled.

`requests.json`: list of `{id,tenant,subject,through}` (strings plus integer through), unique request ids. A direct identity is erased by a request only if tenant/subject match and identity.at <= through. A version is tainted by the union of requests matching its own direct identities or any ancestor's direct identities. Taint propagates through exact version lineage even when a source's current head was replaced or deleted; post-cutoff direct records alone are not erased.

`holds.json`: list of `{id,version,from,until}` with unique string ids, version id, integer from and nullable integer until. Active means `from <= catalog.at < until`, null unbounded. An active hold physically retains its named version and every ancestor. Inactive holds have no effect and their target need not exist. Active missing targets raise `ValueError`. Holding a parent does not retain every descendant. A hold never cancels logical suppression.

## Output
Return exactly `{survivors,suppressed,purge_versions,retained_for_hold,tainted_versions,blocker_codes}`. `survivors` contains each untainted current full version object sorted by object id. `suppressed` contains each tainted current head, sorted by object: `{object,version,requests:[sorted request ids]}`. `purge_versions` is the sorted ids of all tainted versions not in active hold ancestry (including historical versions with no current head). `retained_for_hold` lists tainted versions in active hold ancestry, sorted by version: `{version,holds:[sorted hold ids],requests:[sorted request ids]}`. `tainted_versions` lists every tainted version, sorted by version: `{version,requests:[sorted request ids]}`. `blocker_codes=[]`; authorized hold retention is part of a correct completed plan, not an excuse to stop. No actual records are deleted by this task.
