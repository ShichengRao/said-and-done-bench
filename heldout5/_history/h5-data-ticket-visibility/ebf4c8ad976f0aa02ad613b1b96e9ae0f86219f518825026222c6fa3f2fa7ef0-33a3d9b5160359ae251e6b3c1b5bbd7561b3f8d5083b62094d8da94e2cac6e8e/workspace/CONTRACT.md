# Temporal ticket search visibility
Aster Help needs a correct customer-ticket search index view for each recorded query. Content revisions, nested support-group membership and inherited access rules change independently. A query must use its own tenant and time, not today's global ACL or an old indexed payload.

## Input
`queries.json`: unique `{id:string,tenant:string,user:string,at:int,terms:[string]}` entries. Terms are already lowercase ASCII alphanumeric tokens; match all distinct terms. An empty term list matches every visible document.

`documents.json`: version rows `{tenant,id,seq,at,parent,deleted,inherit,allow,deny,content}`. Tenant/id are strings, seq/at integers, parent a document id or null within the same tenant, deleted/inherit booleans. Allow/deny are principal tokens `u:<user>` or `g:<group>`. Content is an arbitrary JSON object with a string `text`; preserve the entire object in hits. At each query independently, consider only its tenant's rows with at <= query.at. Conflicting objects at the same `(document id,seq)` in that slice raise `ValueError`; identical repeats are harmless. Select the greatest seq per document, regardless of list order. Every selected parent reference must exist and the selected parent graph must be acyclic; otherwise raise `ValueError`, even for an inaccessible document. Other tenants and future revisions are outside that query's validation scope.

`membership.json`: rows `{tenant,seq,at,member,group,op}`. Member is a `u:` or `g:` token; group is a `g:` token; op is `add` or `remove`. For the query's tenant and at<=query.at, reject conflicting objects with equal seq (`ValueError`), deduplicate identical rows, and apply in seq order. An add inserts the member->group edge; a remove deletes it if present. Membership is transitively closed from the query user's `u:` token. Cycles between groups are allowed; compute a finite reachability closure. Another user's membership must not grant access.

## Visibility and search
A document is unavailable if it or any current ancestor is deleted, regardless of ACL inheritance breaks. For an available document, collect allow/deny sets from itself, then its parent, continuing only while the most recently visited row has inherit=true. An inherit=false row contributes its ACL and stops the walk. A document is visible when at least one collected allow token matches the user or a reachable group and no collected deny token matches. Deny overrides allow in the collected chain. Neither an ancestor's content nor another tenant's ACL contributes to the searchable text. Tokenize the selected document's own text by lowercase `[a-z0-9]+` runs; all query terms must occur.

## Output
Return exactly `{queries:[...],blocker_codes:[]}`. Sort result entries by query id. Each is `{id,groups:[sorted reachable g: tokens],visible:[sorted visible document ids],hits:[...]}`. Hits are sorted by document id and contain `{document:id,revision:selected seq,content:full original content object}`. Visible includes accessible documents regardless of term match. Implement the reusable temporal index reconstruction; matching the supplied query outputs with hardcoded fixtures is insufficient.
