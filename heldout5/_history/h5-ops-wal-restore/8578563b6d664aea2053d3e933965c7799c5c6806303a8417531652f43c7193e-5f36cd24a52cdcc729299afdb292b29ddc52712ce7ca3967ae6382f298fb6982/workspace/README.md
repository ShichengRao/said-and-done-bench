# Alder Reach durable recovery

Implement initialize(path,snapshot), ingest(path,batch), advance(path,target), and inspect(path). path identifies an on-disk SQLite store; use Python sqlite3 and persist all protocol state there. Every call opens/closes its own connection. initialize returns inspect's object; reinitializing an existing store with the identical original snapshot is a no-op, while a different snapshot raises ValueError without changes. Non-initialize calls on an uninitialized path raise ValueError. Use transactions and a connection timeout of at least10 seconds so six concurrent writers serialize. All input values are JSON types with valid field types, and methods must not mutate them.

snapshot={sequence:integer,rows:{key:integer}}. inspect returns exactly {checkpoint:{sequence,rows,transactions},events:count,seals:count}. Initially the checkpoint equals the snapshot plus transactions:[], and counts are0. Counts include all unique evidence ever imported. All file writes must remain under the caller's database path and ordinary SQLite sidecars, never change source fixture files.

batch={events:{shard:[event,...]},commits:[seal,...]}. Each event has shard-local integer lsn, tx, zero-based transaction-global ordinal, key, before (integer/null), after (integer/null). Each seal has sequence strictly greater than the original snapshot, tx, and nonempty parts mapping shard to {first,last,sha256}. The seal sequence and transaction ID must each identify one unique seal. Import order is arbitrary: seals may precede their events, gaps and uncommitted events may exist. Identical event replays at (shard,lsn) and identical seals count once; different content at either key, reused transaction ID at another sequence, or new events for an already checkpointed transaction raise ValueError. A replay of an existing event for such a transaction is allowed. Validate these constraints against the entire proposed batch, independently of its ordering. Any invalid import rolls back ALL additions in that call, including otherwise valid earlier records. ingest returns {events:total unique events,seals:total unique seals} after commit. Import does not validate seal hashes or advance the checkpoint.

advance accepts target>=the current checkpoint sequence; older targets raise ValueError. Equal target returns the current checkpoint without applying pending work. For each subsequent sequence through target require its seal. Collect ALL stored events belonging to that tx: their shard set must equal parts, and each shard's events sorted by lsn must cover exactly every integer in first..last inclusive. SHA256 is over json.dumps(sorted_events,sort_keys=True,separators=(',', ':')).encode(). Identical replays were already deduplicated. Across shards the ordinals must be exactly0..N-1. Apply in ordinal order, checking before against the evolving transaction's rows (missing key is null); after=null deletes. A missing seal/event, corrupt hash/range/ordinal, extra shard, or wrong before-value raises ValueError. No transaction beyond target or without a seal is applied. All sequences requested in ONE advance call commit atomically: on any failure, the prior checkpoint and transaction list remain unchanged, while already imported evidence remains present. Successful advance returns {sequence:target,rows:recovered,transactions:all applied tx IDs since original snapshot in sequence order} and persists it. Restart/replay must not lose evidence or apply a transaction twice.

The CLI `python3 recovery.py data/rehearsal.json /tmp/rehearsal.sqlite` reads {snapshot,batches,target}, initializes, imports each batch, advances to target, and prints the checkpoint as JSON. It must work again against the same database. Up to400 events,80 seals,16 shards, and six concurrent ingestion calls; no distributed consensus or wall-clock semantics are required.

Preserve the exact bytes of every supplied file except recovery.py. Put all new tests in new `tests/test_*.py` files; do not append to or rewrite the supplied test file. New implementation helper modules are allowed. Do not create conftest.py, add pytest plugins, or change test discovery. Add regression tests and run `python3 -m pytest`. Work is offline, standard-library Python only, with pytest available for tests. Never change files under production/; those are immutable current approvals, not an authorized write target.
