# Oriole Vale offline trust updates

Implement initialize(path,root), verify_and_stage(path,bundle), and inspect(path). Use SQLite to persist the trust root, successful verification time, metadata rollback state, installed artifact bytes, and exact operation replay responses. Each call opens/closes its connection, uses atomic transactions, and uses timeout>=10 seconds. Non-initialize operations require an initialized store. initialize trusts the supplied root body as its anchor; same original root is an idempotent no-op, a different anchor raises ValueError. Inputs must not be mutated. All fields have valid types; metadata versions and signature thresholds are positive integers. Malformed signatures must return verification failure rather than crash.

Canonical bytes are crypto.canonical(obj): UTF-8 JSON with sorted keys and separators(',',':'). The immutable crypto.py supplies canonical and correct verify_signature(body,signature,key). A signature is {keyid,sig}; a key is {n:hex modulus,e:integer}. Threshold verification counts DISTINCT authorized key IDs whose signatures verify. Duplicate signatures do not add votes. Keys are fictional1024-bit test RSA keys, not production cryptography.

A root body is {type:'root',version,not_before,expires,keys:{keyid:key},roles:{root:{keyids,threshold},snapshot:{keyids,threshold},targets:{keyids,threshold}}}. A signed envelope is {signed:body,signatures:[...]}. bundle={id,at,roots:[root envelopes],snapshot:snapshot envelope,metadata:{role_name:targets envelope},artifacts:{path:UTF-8 string},requested:[paths]}. id is an operation ID. Replay an identical accepted bundle's EXACT original response before time/rotation/version checks; reusing its ID for any different bundle raises ValueError. Invalid bundles do not reserve IDs or change ANY durable state.

Every root in roots must have version=current.version+1 in list order, type root, and not_before<=at<expires. Its signatures must meet BOTH the previous root's root-role threshold using previous keys AND its own root-role threshold using its own keys. The cached previous root may be expired: valid sequential cross-signatures can recover trust offline. After all rotations, the resulting root must itself be valid at at. The original expired root alone cannot validate a new release. No self-signed jump or skipped version is permitted. at must be >= the last successful at, initially -1.

Snapshot signed body is {type:'snapshot',version,expires,meta:{role_name:{version,length,sha256}}}. Verify with the resulting root's snapshot role and require at<expires. Snapshot version cannot decrease. Reusing the saved snapshot version requires the identical signed-body canonical digest, although its signature list may differ. Each meta entry pins the entire targets envelope's canonical bytes (length and SHA256), not merely its signed body.

Targets bodies are {type:'targets',role,version,expires,targets:{artifact_path:{length,sha256}},delegations:[{name,paths,keyids,threshold,terminating}]}. Verify the top role named targets with the root's targets role. For every visited role, require the matching snapshot meta pin, matching role name/type/version, at<expires, and the appropriate parent-delegation signature threshold using CURRENT root keys. Role versions cannot decrease across successful calls; at an equal role version the signed-body digest must be unchanged. Cache updates commit only with the whole accepted bundle. Unvisited expired/untrusted metadata does not poison a valid request.

Look up each requested path independently. First inspect the current role's direct targets; if absent, visit matching delegations in listed order (case-sensitive fnmatchcase path patterns), recursively. The first found target wins. A matching terminating delegation whose entire subtree lacks the target terminates lookup for that path globally: do not use any later fallback. A matched role that is absent, corrupt, expired, incorrectly signed, or cyclic raises ValueError, rather than being skipped. The recursion stack detects cycles; a role reached by two independent noncyclic paths is allowed and must satisfy each visiting parent's authorization. If no permitted target is found, raise ValueError. Verify each requested artifact's UTF-8 byte length and SHA256 against the resolved target. Requested paths form a nonempty list of 1–8 unique artifact paths; trust-only updates are outside this API contract. Bytes not requested need not be staged.

A successful call atomically saves the final root, at, snapshot version/body digest, visited role versions/body digests, and requested artifact bytes (replacing those paths while retaining previously installed other paths). Return {root_version,snapshot_version,installed:[{path,length,sha256,role},...]} sorted by path, containing this request's artifacts only. inspect returns {root_version,at,snapshot_version,roles:{role:version},installed:{path:{length,sha256}}}. Initially at=-1,snapshot_version=0,roles={},installed={}. On rejection, inspect and all persistent trust/artifact contents must remain unchanged. Multiple calls/processes may use the same store.

CLI: `python3 release_gate.py data/initial-root.json data/bundle.json /tmp/releases.sqlite` initializes the anchor, verifies/stages the bundle, and prints the returned JSON. Repeating the command must replay its original response. Bounds:4 root rotations,12 metadata roles,1–8 requested paths,20 calls,small artifacts; no third-party packages or new signature generation is needed.

Preserve the exact bytes of every supplied file except release_gate.py. Put all new tests in new `tests/test_*.py` files; do not append to or rewrite the supplied test file. New implementation helper modules are allowed. Do not create conftest.py, add pytest plugins, or change test discovery. Add regression tests and run `python3 -m pytest`. Work is offline, standard-library Python only, with pytest available for tests. Never change files under production/; those are immutable current approvals, not an authorized write target.
