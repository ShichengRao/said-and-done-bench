# Oriole Gate offline release verifier

Implement `release_gate.closure(bundle)`. The air-gapped staging area contains releases from several build lanes, including untrusted and obsolete material. Return the complete verified dependency closure for `requested`, or raise `ValueError` if any requested/transitive release is inadmissible. Unrelated bad releases do not poison a valid closure. Never alter the input.

A release envelope is `{manifest, signatures}`. A reference is `{package, version, sha256}` where the digest pins the full canonical manifest. Canonical bytes are UTF-8 `json.dumps(obj, sort_keys=True, separators=(',', ':'))`. A manifest contains package, version, numeric build, role, not_before, expires, artifact (name in bundle.artifacts), artifact_sha256, dependencies (list of references). Artifacts are UTF-8 strings. All reference identities and content hashes must agree. All dependencies must exist and validate. Dependency cycles and two different manifests for the same package in one closure are forbidden; a diamond referencing the same digest is allowed.

`policy.at` is the verification timestamp. Both manifest and signing key must be valid at that timestamp: not_before <= at < expires. A key with non-null revoked_at is unusable at or after that timestamp. `policy.minimum_build[package]` is the inclusive anti-rollback floor (default zero).

`policy.roles[role]` provides `packages` (case-sensitive shell glob patterns; Python fnmatchcase), authorized keyids, and threshold. Manifest package must match a role pattern. Each threshold vote must come from a DISTINCT authorized, currently valid, unrevoked key and a valid signature. Repeated signatures from one key count once. Keys under policy.keys contain hexadecimal RSA modulus n and integer e. A signature is a modulus-width hex string representing standard RSA PKCS#1 v1.5 with SHA-256 of canonical manifest bytes; SHA-256 DigestInfo prefix is hexadecimal 3031300d060960864801650304020105000420. Check exact padding (00 01, at least eight FF bytes, 00, DigestInfo+32-byte hash); reject non-width or out-of-range signatures. The fictional fixture uses 1024-bit test keys solely to exercise protocol verification; never generate new signatures or change trust policy to pass a release.

Return entries `{package,version,sha256}` sorted by package. Standard-library implementation is sufficient (integer modular exponentiation). Inputs have valid field types and unique manifests by hash. Only malformed signatures require graceful handling. Preserve original tests, policy, and fixture data. Add tests; run `python3 -m pytest`.
