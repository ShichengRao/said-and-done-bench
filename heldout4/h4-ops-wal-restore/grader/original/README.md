# Alder Quay recovery tool

Restore a multi-shard ledger from an offline snapshot and write-ahead-log bundle. A recent split transaction produced a correct-looking balance on one shard and lost its counterpart. Implement `recovery.restore(bundle, target_sequence)` without mutating its argument.

The snapshot has `sequence` and `rows` (key to integer). `segments` maps shard names to event lists. Event fields: shard-local `lsn`, `tx`, transaction-global zero-based `ordinal`, `key`, `before`, `after`. `None` means absent/deleted. Replayed events with identical shard+lsn and identical contents are duplicates; conflicting duplicates are corrupt and must raise `ValueError`. Physical event/commit order is arbitrary. Uncommitted events must never be applied.

Commit seals have globally contiguous `sequence`, a transaction ID, and `parts`: shard to `{first,last,sha256}`. For every sequence strictly after the snapshot through the requested target, require exactly that commit and exactly its listed shards. Each shard's transaction events sorted by LSN must cover every integer in the inclusive first..last range. Hash is SHA-256 of that event list serialized as `json.dumps(events, sort_keys=True, separators=(',', ':')).encode()`; identical replay duplicates count once. Transaction ordinals across shards must be exactly 0..n-1. Apply events in ordinal order atomically, checking each before-value against the evolving transaction state. A precondition failure, corrupt seal/digest/range/ordinal, conflicting commit sequence, missing commit, or target before the snapshot raises `ValueError`. Events belonging only to later committed transactions are not applied or validated as target transactions.

Return `{'sequence': target_sequence, 'rows': recovered_rows, 'transactions': applied_tx_ids_in_commit_order}`. Inputs are JSON types and valid field types; no need to repair malformed JSON. Use standard-library Python only. Preserve README, original tests, and fixture data; add tests freely. Run `python3 -m pytest`.
